# 散舰指定归队（试验功能）

> 此方案已由按需“散舰整理工具”替代，已从核心菜单和构建清单移除。
> 新方案见 `SCATTERED_FLEET_ORGANIZER.md`；以下仅保留旧试验记录。

此功能解决补员中断后的小舰队整理操作，不修复引擎的原补员目标关联。
当前未通过实机验收；电脑控制工具未获准操作群星窗口，不能将静态检查视为游戏内验证。

## 使用

打开星政中枢 → 舰队容量与指挥上限菜单 → **散舰指定归队（试验）**。
先选接收舰队，再逐个点击要归队的散舰。每页六支，可翻页或回到第一页。
登记后关闭菜单即可；不会自动选择任何其他舰队。

- 第一版只列出与目标同星系、拥有一至三艘舰船、无领袖且未交战的散舰。
- 舰船限原版护卫舰、护卫艇、驱逐舰、巡洋舰、战列舰和泰坦；含其他舰型的舰队不显示。
- 排除租借、联邦舰队、非本国控制舰队和已有合并命令的舰队。
- 目标可以正在交战。登记后一天首次检查；交战、容量不足或星系不同，每五天重试，最长一百八十天。
- 目标被摧毁、所有权/控制权变化、来源获得领袖或不再符合条件时，放弃请求。
- 发出原版合并命令时会清除所选散舰原有命令。不传送、不复制、不删除舰船。
- “取消尚在等待的散舰归队”只取消等待中的请求；已发出的命令在原版舰队界面取消。
- 需要先手动集中异地散舰。本版不识别原补员归属，也不负责把异地舰队带到前线。
- 多支散舰同时申请时，最终合并仍受原版引擎限制；不会提前预留舰队编制，也不会重写舰队管理器模板。

## 必须完成的实机验收

使用测试新档或存档副本，只启用测试构建；不要同时启用同源开发版/公开版。
可用 `event auto_qol_reassembly.1` 直接打开入口。

1. 同星系放一支主舰队与两支单舰队，选择其中一支归队：应只合并选中者，舰船总数和舰船身份不变。
2. 主舰队处于战斗时登记：不得强制结束战斗；脱战后重试并合并。
3. 指挥容量不足时保持独立；腾出容量后重试，不突破指挥上限。
4. 将来源分配领袖、改变控制权、提前手动合并，或摧毁目标：不得错误合入其他舰队。
5. 登记后使用取消入口：等待中的舰队不得收到合并命令。
6. 同时登记给不同目标：每支来源必须保留自己的目标；后续打开菜单不得覆盖旧请求。
7. 超过六支舰队翻页、返回第一页；摧毁某页舰队后重新打开，不得出现可执行的旧目标按钮。
8. 等待中保存、退出再读档：事件目标和等待逻辑应保留；一百八十天后请求应过期。
9. 来源进入战斗/主舰队移出星系后保持等待，不传送、不强行追踪；返回同星系可再尝试。
10. 检查 `logs/error.log`：尤其确认 `find_closest_fleet` 下的 `merge_fleet = { target = this }` 被当前 4.5 引擎接受并实际完成合并。

## 接口依据与限制

本机 4.5 引擎生成的 `logs/script_documentation` 包含 `queue_actions`、`has_fleet_order`、
`is_in_combat`、`fleet_size`、`command_limit`、`save_event_target_as` 等接口。
原版 `events/biogenesis_crisis_events.txt` 使用带唯一 ID 的 `find_closest_fleet` 筛选。
本地已有模组也存在队列合并动作的用例，但这不能代替本功能的实机验收。
没有在导出的 scopes 中找到原补员目标读取接口，因此不推断原归属。
