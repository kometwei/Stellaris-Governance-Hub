# 巨构工程署：批量启动下一建设阶段

入口：法令“打开星政中枢” → “巨构工程署”。选择全部或某一类型，查看预览，确认后重新扫描并批量启动下一阶段。类型列表有两页，使用底栏翻页。控制台测试入口：`event auto_qol_mega.1`。

本版支持 12 类、38 条明确建设转换：戴森球、科学枢纽、哨兵阵列、物质解压器、战略指挥中心、巨型艺术设施、星际集会、巨型船坞、量子弹弓、电弧熔炉、戴森云和环世界。每次每座最多一阶段；环世界框架与区段分别按实际阶段处理。不新建、瞬间完工或自动续建。

只处理操作玩家拥有的巨构，跳过正在施工、已完工、科技或阶段条件不足的对象。保留原生 `can_be_upgraded` 检查，并编译目标阶段的 prerequisites、potential 和 possible；按剩余资源逐座判断。预览用影子预算和施工额度模拟，不修改资源或巨构；确认时重新计算，所以预览不是保留名额或报价锁定。遍历顺序由引擎决定，预算不足时不能承诺优先升级某一座。

## 排除范围

- 整条星际大炮／戴森枪 `dyson_gun_*` 建设链。此机版本开火使用 `scripted_action = { dyson_shoot }`，没有接入工程署。
- 危机巨构、武器发射、模式切换、隐藏阶段、事件奖励（包括科学枢纽第四阶段）、废墟修复。
- 巨型艺术设施的额外特殊阶段、戴森云转戴森球等未列入白名单的转换。
- 某个来源阶段如果在原版定义中出现多个后继，生成器会排除该转换。
- 本地生成版发现播放集 Mod 重定义白名单来源或目标时，排除受影响转换，不把 Mod 内容当作原版代办。

公开版按原版定义生成，不能在运行时检测其他 Mod 是否覆盖同名巨构。改变巨构规则的播放集请重新生成本地版；首版不承诺兼容 Mod 改写后的费用和回调。

## 费用与施工

生成器读取本机游戏 `common/megastructures` 中的原始定义，完整保留所有条件 cost 块、重复资源项、mult 和全局／文件内数值常量。不能简单硬编码“科学枢纽多少钱”；本机戴森球第一阶段等定义甚至包含额外的无条件合金项。生物帝国的合金／食物分支也按源定义编译。

成本按原版经济类别 megastructures 及其 country 父类别的通用／逐资源成本修正计算。合计修正让某项费用低于原价 10% 时，暂时跳过该项目并显示数量，避免猜测引擎的极端成本下限。此版未支持 Mod 的自定义费用类别、巨构实例上的特殊费用修正或额外脚本付款。

先核实预算，再调用 `upgrade_megastructure_to`。只有原生调用后确认 `is_upgrading = yes` 才记成功并付款；调用前后读取库存，只补扣计算费用尚未支付的差额，避免原生接口已经收费时重复扣费。费用不预扣，因此原生启动失败不会由本工具收费。正常建设时间和完工行为交给引擎，不调用 `finish_upgrade`，不复制或重建巨构。

普通多阶段项目使用构建时读取的 `MEGASTRUCTURE_BUILD_CAP_BASE` 加当前帝国 `country_megastructure_build_cap_add`，取整数施工额度。当前正在施工的其他多阶段巨构也占额度；原版标为 none 或 self_type 的项目不占共享多阶段额度。无法识别的 Mod 施工保守计入共享额度，且仍保留原生升级许可检查。

没有新增每月／每日钩子，没有覆盖原版巨构界面，U 键补丁继续独立使用。入口和往返使用已验证的原生事件选项底栏，不用效果按钮另开可见窗口。

## 构建与验证

```text
python tools/build_megastructure_office.py
python tools/build_hub_gui.py
python tools/test_megastructure_office.py
python tools/test_hub_gui.py
python tools/test_native_dashboard_footer.py
python tools/build_release_profiles.py public
```

公开版与本地版发布流程都会生成工程署；`megastructure-office-build.json` 记录启用转换、跳过项、施工基数及源文件哈希。新 GUI 和 scripted effect 文件需要完整重启游戏。

脚本模拟覆盖预算、额度、条件、单阶段、失败不付款、原生已付款不重复扣费、生物费用、常规折扣、特殊阶段排除及重复构建；不等于已完成游戏内验收。

## 游戏内验收

1. 完全退出并重启游戏，使用测试存档副本，进入工程署；确认分类、翻页、返回首页和关闭均正常。
2. 准备至少两座可升级普通巨构，先记下原生按钮显示的费用、工期和当前资源。预览不应扣费或开始施工。
3. 确认后核对开工数量、实际扣款与原生按钮报价；同时测试无折扣、常规成本折扣、生物帝国。费用计算和原生接口行为尚待此步骤实机确认。
4. 额度为一时，应最多开工一座普通多阶段巨构；已有一座施工时，其他此类项目应跳过。额外施工额度允许相应数量。电弧熔炉／戴森云按原版豁免规则处理。
5. 预览后花掉资源再确认，应重新判断预算；再次点击不应重复扣费、重复下令或连升两级。
6. 放入星际大炮、科学枢纽事件阶段、废墟或特殊 Mod 武器，确认它们没有被处理。最后推进时间，核对普通巨构完工效果与日志是否正常。

如日志或实测显示付款、工期、回调、原生许可含义与假设不同，应先停用该转换并修正，不能把离线测试视作引擎行为的证明。
