# 🪐 Stellaris Mod 开发架构、实机避坑红线与持久经验备忘录

本文档持久记录了在《群星》（Stellaris）Mod 开发与多次实机调试中沉淀的核心机制、避坑红线与指令清单，防止后续版本迭代遗忘关键教训。

## ⚡ 二、控制台热重载指令清单 (修改代码后无需重启游戏)

在游戏中按键盘左上角 **`~`** 键打开控制台，输入以下指令可**秒级重载代码（0.5秒生效）**，极大节省反复重启游戏的时间：

| 控制台热重载命令 | 生效范围与用途 | 适用场景 |
| :--- | :--- | :--- |
| **`reload loc`** | **重载全部汉化/本地化文本** | 修改了文本、补丁修复了双重 BOM、修改描述后使用，立即刷新中文！ |
| **`reload events`** | **重载全部事件与弹窗逻辑** | 修改了内阁指派事件、选项按钮、触发效果后使用，立即加载新事件！ |
| **`reload edicts`** | **重载全部法令** | 修改了法令数值、开销或增减法令后使用。 |
| **`reload gui`** | **重载全部 UI 界面** | 调整了窗口布局、数字键盘位置、按钮图标后使用。 |
| **`reload defines`** | **重载引擎全局底层常数** | 修改了舰队容量、单舰队指挥上限、招募池代谢周期后使用。 |
| **`reload traditions`** | **重载传统定义** | 修改了传统节点效果与定义后使用。 |

> **提示**：仅在“启动器中勾选/启用了全新外部大 Mod”或“增加了底层 3D 舰船模型/音频”时才需要真正重启游戏；日常改脚本、改文字、调参数**只需输入上述 `reload` 指令即可**！

## 🚫 三、绝对不可触碰的 6 大避坑红线 (血泪实战逆向总结)

### 🔴 避坑 1：法令定义严禁设置 `length = 0`（底层除以零瞬崩）
- **致命现象**：关闭控制台弹窗或打开【法令】列表界面的瞬间，游戏无征兆闪退，系统生成 Dump 显示 `Unhandled Exception C0000094 (EXCEPTION_INT_DIVIDE_BY_ZERO)`。
- **根本原因**：
  - 群星引擎中，一旦在法令块声明了 `length`，底层渲染系统就会认为这是带有时限的法令，并为该法令控件绘制持续时间进度条。
  - 进度条百分比的底层汇编计算逻辑为：
    ```assembly
    mov r14d, eax          ; 读取法令的 length (若设置 length = 0 则 r14d = 0)
    imul eax, r10d, 100    ; 已经过天数 * 100
    cdq
    idiv r14d             ; ⚠️ 除以 r14d！当 r14d 为 0 时直接硬件除以零异常崩溃！
    call [rsi + 0xb0]     ; 调用 UI 进度条控件更新函数 (SetProgress)
    ```
- **铁律准则**：
  - 菜单入口类按钮法令**一律设置为 `length = 1`**（1天后自动完成重置，分母为 1 绝不除以零，主流大 Mod WSG 等的标准规范写法）。

---

### 🔴 避坑 2：本地化文件 (.yml) 必须严格保持【唯一单 UTF-8 BOM】
- **致命现象**：游戏内所有事件标题、选项按钮、法令名称变成英文生硬变量名（如 `auto_qol_menu.1.name`、`edict_auto_qol_menu`）。
- **根本原因**：
  1. 普通 UTF-8（无 BOM）：群星 Clausewitz 引擎直接不识别中文，抛弃文件。
  2. **双重 BOM (`\xef\xbb\xbf\xef\xbb\xbf`)**：脚本二次写回时未先剔除既有 BOM，写入了两个 BOM，导致引擎判定文件头损坏，整份本地化失效！
- **铁律准则**：
  处理 `.yml` 文件时，必须先清除首部的所有 `\xef\xbb\xbf` / `\ufeff` 字符，再以唯一一个 UTF-8 with BOM 写入，开头严格紧贴 `l_simp_chinese:\n`。

---

### 🔴 避坑 3：全局参数覆盖 (Defines) 必须强制加上 `zzz_` 最高优先级前缀
- **致命现象**：在 Mod 里把舰队容量上限调到了 100 万甚至 10 亿，但在游戏里看依旧显示 `最大: 50000 达到海军容量上限`，完全不生效！
- **根本原因**：
  - 群星加载 `common/defines/` 目录时，是**按文件名 ASCII 字母升序加载，后面的覆盖前面的**！
  - 工坊里有其他 Mod（如 `xiaoai_defines.txt`，`x` 开头）写了 `NAVAL_CAPACITY_MAX = 50000`。
  - 如果我们的文件名是 `auto_qol_fleet_defines.txt`（`a` 开头），就会被后面的 Mod 强行盖回 50000！
- **铁律准则**：
  所有涉及引擎全局常数覆写的文件，必须命名为 **`zzz_auto_qol_fleet_defines.txt`**（`zzz_` 确保排在所有 Mod 之后加载，拥有最终绝对统治权）。

---

### 🔴 避坑 4：传统安全审计不仅是“防闪退”，必须做到“阵营与身份隔离”
- **致命现象**：玩家玩普通人类国家，运行全选或普适包后身上莫名其妙被强塞了一堆舰娘（`tr_wg_`）、深海栖姬（`tr_sh_`）或蜂巢无人机传统，极度违和。
- **根本原因**：
  - 控制台的 `activate_tradition <id>` 命令是底层硬指令，它在执行时**完全忽略传统树的 `potential` 和政体条件**！
  - 之前的普适包只排查了“语法不崩溃”，把舰娘等 Mod 里的非崩溃节点混了进去。
- **铁律准则**：
  1. **恶性崩溃黑名单（永久封杀）**：
     - `tr_tt_ultralimit_*`（包含 -10000 劳工政治权重恶性缺陷，导致 F2 相对实力除以零崩溃）。
     - `tr_adaptability_homura/kyoko/madoka/mami/sayaka`（包含 -1000% 建造时间恶性缺陷，导致进度条除以零崩溃）。
  2. **领袖池特质污染黑名单（永久封杀）**：
     - **`tr_aptitude_finish`**（原版天赋收官，带有 `leader_initial_traits_add = 1` 与 `every_pool_leader = { add_trait }`，是导致候选人特质堆叠、破坏 Mod 特质生态与卡顿的罪魁祸首！）。
  3. **阵营专属隔离**：
     - `unlock_safe_only.txt` **严禁包含任何 `tr_wg_*`、`tr_sh_*`、`tr_hsr_*` 等特定背景专属节点**，保持 100% 普适纯净。

---

### 🔴 避坑 5：事件批量执行指令必须包裹在 `hidden_effect = { ... }`
- **致命现象**：游戏内点击助手界面的传统解锁选项时，游戏卡死、无响应或选项点不下去。
- **根本原因**：
  - 如果在单个 option 下直接暴露几百个 `activate_tradition = xxx`，群星在渲染窗口时会试图为这几百个传统生成长篇巨幅的实时 Tooltip（鼠标悬浮提示）。
  - 主线程在瞬时计算海量岗位修正与修正文本时直接引发卡死。
- **铁律准则**：
  大批量执行效果时，**必须全部塞进 `hidden_effect = { ... }`**，只用一条简洁的 `custom_tooltip` 展示说明，瞬发零卡顿。

---

### 🔴 避坑 6：内阁管理严禁在文本事件中暴力嵌套（防爆栈闪退）
- **致命现象**：点击内阁功能连续闪退，日志刷满 `Failed to assign council position to council`。
- **根本原因**：
  - 帝国内阁的槽位上限只有 3~6 个，在事件里强行调用 280 多个席位的 `set_council_position_to_council`，或者在 option 里嵌套上百重 if-else 试图在文本弹窗里管理领袖，直接导致引擎堆栈溢出闪退。
- **铁律准则**：
  - 采用**分类导航大厅**模式：将科研、经济、军事、政务分开管理；
  - 席位指派加入前置插槽校验与空闲过滤，确保绝对稳定。

## ⚙️ 四、核心参数设计备忘

1. **舰队容量天花板与实际加成的关系**：
   - **`NAVAL_CAPACITY_MAX = 10000000` (1000 万)**：
     - 这是“容器大小（天花板）”，定义在 `zzz_auto_qol_fleet_defines.txt`。
     - 它不是送给玩家的免费舰容，而是**防止玩家加了容量后被原版 9999 或其他 Mod 50000 强行封顶截断**。
   - **AI 是否会享受？**：
     - **绝对不会！** 助手控制台严格限制 `potential = { is_ai = no }`，所有实际加成 100% 专属于玩家帝国。
