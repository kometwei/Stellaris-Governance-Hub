# 散舰整理工具（按需试用版）

目的：事故发生后，批量把同一设计的零散舰队重新编队；不恢复原补员归属。
这是独立插件，可与星政中枢并用，不依赖补员诊断或补员倒计时插件。
现阶段已通过静态与离线逻辑检查，**未完成原版命令与跨星系合并的实机验收**。

## 当前版本0.1.8（优先于下方旧版记录）

### 0.1.8已完成归队的旧接收队可重新合并

确认此前全部归队已完成或取消，点击首页“释放旧容量预留”后，为工具接收队设置
`qol_sort_regroup_ready`，允许其和同设计散舰一起重新装箱，不受三艘门槛限制。
普通大舰队没有接收队身份，仍排除；手动保护、领袖、战斗、任务和设计检查仍有效。
之前版本释放过预留也需在本版重新执行一次，才能取得重新编组标记。

未释放的接收队仅作为目标；即使预留规模等于实际规模，也不自行判断归队完成。
任何目标接收新请求时移除重新编组标记，并累计预留。确认及执行时再次检查来源标记、
预留不大于实际规模、设计与状态，避免将仍接收舰船的旧接收队编走。没有后台检查。
取消预览不消耗重新编组标记，不发命令；手动保护可随时阻止已释放接收队参与。

22项离线回归通过：新增第8/11舰队对应的2+4艘、60/1100场景；普通五艘大舰队和
受保护旧接收队不参与；未释放的接收队不互相合并；预览后新增预留会阻止其作为来源。
原生合并与航行仍需实机核验。

### 0.1.7一键取消手动保护

首页添加“一键取消全部手动保护”，确认后清除当前全部自有舰队的`qol_sort_protected`，
覆盖逐支设置和保护全部。接收队身份、容量预留和现有命令保留，返回首页后可重设例外。
此按钮不替代“释放旧容量预留”；二者用途独立。

### 0.1.6保护名单不再限制舰船数量

玩家第一舰队在最近存档中有五艘、战力约16016，且已带手动保护标记；旧名单因其超过
三艘且不是工具接收队而隐藏，导致“保护全部”之后无法在名单中解除大舰队保护。
名单现在列出所有通过原有自有常规军事舰队条件的舰队，不限制数量；候选范围不扩大。
解除保护也不会让超过三艘的普通舰队自动成为整理来源或接收队。
19项离线检查通过，新增五艘/200指挥点舰队可显示、解除保护且仍不参与散舰规划。

### 0.1.5筛选开销优化

将来源数量门槛、保护标记、领袖、任务、接收队标记及剩余容量判断前置，
通过后才检查舰船可设计性和设计一致性。保护名单也先判断数量或接收队身份。
优先排除正常补员合并命令，仍保持三轮按需扫描和相同的候选规则。
18项离线回归通过；新增场景加入100支各100艘的大舰队以及受保护、战斗、补员和
预留已满的接收队，确认不增加逐艘检查次数，规划结果不变。
此结论基于离线短路执行模型，游戏触发器实际开销与原生命令仍需实测。

### 0.1.4接收队与命令修订（保留）

修复旧接收队被永久排除：此前整理的接收队可以继续接收同设计散舰，超过三艘也可参加，
但不会被作为来源编走。玩家手动保护仍排除。每设计每批复用一个有余量的旧接收队，
其余整支散舰按next-fit装箱；多支旧接收队不会互相吞并，不保证一次填满全部历史空位。

容量以`max(实际规模, 已预留总规模)`为基数。预留跨批次保留，防止在途舰船抵达后超编；
失败、取消或损失的容量不会自动释放。确认本工具全部归队已完成或取消后，
从首页使用“归队已全部结束：释放旧容量预留”。仅接收队停止移动不代表归队结束。
旧版本没有预留记录，升级后须在归队全部结束时释放一次，旧接收队才会重新纳入。
保护名单现在包含超过三艘的工具接收队，只切换玩家保护，不删除接收队身份和容量记录。

预览做清理、接收队、新散舰三轮舰队扫描；旧接收队会检查其全部舰船是否同设计。
参与的接收队也计入256支规划限额和界面候选数。没有后台扫描。

本机4.5.2的`merge_fleet`动作构造器支持标量目标，默认允许FTL；其块式`target`解析
分支在读完作用域后又落入布尔读取，与`Malformed token: event_target:...`相符。
现改用`merge_fleet = event_target:...`，去掉`find_closest_fleet`包装。
依据是只读检查本机执行文件的解析路径，**尚非实机成功证明**；未修改游戏执行文件。
确认映射在来源作用域用`@this`读取，移除可能未赋值的`qol_sort_commit_source`依赖；
原生事件目标上下文仍需核验。

17项离线回归通过，包括1100上限、四艘以上接收队、连续批次预留、实际规模超过预留、
手动释放与保护并存。原生执行、动态事件目标和跨星系寻路仍需验收。
重新启动后先在归队全部结束的测试存档释放一次旧预留，再预览并确认合并。

下方含旧版设计与历史反馈，涉及永久自动保护、两轮扫描、旧命令格式的说明已被上述修订替代。

## 使用

启动器播放集中添加 **散舰整理工具（试验）**，启用后完全重新启动游戏。
在法令中打开同名工具，或使用控制台 `event qol_fleet_sort.1`。

1. 在“保护名单”里保护需要保留的小舰队。只有少数例外需要选择，事故散舰不必逐支点击。
   如果是在事故发生前准备，也可一次保护当前全部舰队；这只是写入保护标记，之后没有定时检查。
2. 点击“扫描并预览本批散舰”。核对候选舰队数、舰船数、设计数、预计编队数和合并请求数。
3. 如需排除某个设计，打开“查看分组／整组排除”，点一次即可排除本批该设计的全部候选。
4. 确认后才尝试下达原版合并命令。来源仍须正常航行；不传送、不复制、不删除舰船。
5. 接收了本批整理请求的目标自动加入保护，避免下一批又把接收舰队编走。保护不会自动过期；
   如需再次整理，等其空闲后在保护名单解除。即便命令失败，自动保护标记仍保留，可手动解除。
6. 超过256支候选时，明确显示留待后续的数量；确认本批命令生效后，再按需点击“预览下一批”。

预览可以取消；取消不会下达任何舰队命令。已确认后的原版命令在原版舰队界面取消。
保护标记随存档保留，卸载不会影响舰船属性；重新启用工具后仍会识别标记。

## 选择范围

- 自有、由本国控制的可移动军事舰队，非租借、非联邦，拥有可用星系作用域。
- 一至三艘军舰、无领袖、不在战斗；允许普通移动、环绕、跟随、返回和正常使用通道。
  补员合并、维修、升级、跳跃预热等任务仍排除。
- 正常携带合并命令的补员舰队会排除；不会提前终止仍在正常进行的补员。
- 排除保护名单、接收过本工具整理请求的目标、本次主动排除的设计组。
- 舰船须有可设计的设计；排除主宰、巨像、焚天神兵，以及非国家所有的舰船设计。
- 每支候选内部也必须完全是同一设计。混合设计小队跳过，不拆成单船。
- 使用实际设计对象匹配，不按舰名或船壳分类。因此相同名字的不同设计版本也不会混编。
- 每支候选的舰队规模不能超过当前国家指挥上限。

工具**无法自动区分**事故散舰与故意保留的小队，保护例外仍由玩家决定。
若已发生事故，不要直接“保护当前全部舰队”，否则当前散舰也会被排除。
任务过滤依据当前已知订单，不是引擎提供的通用状态分类；未导出或第三方新增命令仍可能需要补充过滤。
没有直接可读的补员MIA类型触发器，因此本工具不承诺识别所有失踪状态；
既有合并命令和缺少星系作用域会被排除，其他异常状态仍须实测。

## 编队与开销

预览按当前遍历顺序，使用每个设计一个当前接收桶的 next-fit 装箱：
下一支整队放得下就加入；放不下就作为该设计的下一个接收队。
按 `fleet_size` 占用指挥点数，不能将“一艘泰坦”当“一艘护卫舰”的容量。
不拆小队，因此可能存在未填满的容量，不承诺最优装箱或每队恰好满编。

- 没有 on_actions、造船回调、每日/月度脉冲或定时复查。
- 只有打开菜单、保护操作、预览和确认等明确交互才执行扫描。
- 核心预览是清理与候选遍历两轮舰队扫描，候选内部最多检查三艘船；
  用带作用域后缀的事件目标按设计查桶，不做舰队两两比较。
- 每批最多规划256支，来源到目标的映射只用于当前事件链。
- 可选的分组详情每页固定四个设计，会额外扫描舰队以隐藏同设计的重复分队。
- 确认前再次校验设计、舰队规模、所有权、保护、任务、战斗与当前指挥上限。
  同一接收队的多个请求会扣减同一个预留余额，避免每次都误用同一份空余容量。
- 指挥上限、设计或状态变化时跳过相关请求，不挂后台重试。

这些结构限制了工作量，**不是游戏性能保证**。离线测试耗时不等于实际日切耗时；
大存档、事件目标映射、原版路径计算和大量原版合并命令仍需实测。

## 实机验收（先用测试存档）

1. 把同设计的军舰分成两三支无领袖小队并停止移动。保护其中一支作为对照。
2. 打开工具预览，确认只将未保护小队列为候选；取消后所有舰队命令保持原样。
3. 再预览并确认，观察是否生成原版合并命令、实际完成合并，保护对照不变。
4. 把其中一支候选放到其他星系、停下，再做一次，确认正常跨星系赶路与合并。
5. 混合设计、有领袖、补员合并、维修升级及交战舰队应跳过；不同设计应分别编队。
   普通移动中的来源应在确认后改为归队，接收队本来的移动应保留。
6. 在较低指挥上限下放多支同设计小队，确认多队分组和多个并发请求不超上限。
7. 来源在路上时预览下一批，正在接收来源的目标不得再次变成来源。
8. 确认所有舰船身份、设计、经验与装备保留；保护标记保存读档后仍生效。
9. 查看 `logs/game.log` 的 `QOL_SORT` 和 `logs/error.log`，区分“尝试下达请求”与“实际合并成功”。
   尤其核验原版 `merge_fleet` 动作使用带 `root.event_target:` 前缀目标的解析及跨星系行为。

旧的同星系逐支收编试验已从核心构建清单和中枢菜单移除，源文件仅留作试验记录。
本工具暂时独立注册，不向现有发布成品同步未验收的舰队动作。

## 首次加载反馈（0.1.1修正）

4.5.2实机在加载时拒绝裸 `target = from`，报 `Malformed token: from`；
现改为先保存接收目标，再使用本地已有队列合并用例的 `root.event_target:` 目标格式。
导出的订单文档还包含两个被当前引擎拒绝的旧键：`build_space_station_order` 和
`research_discovery_orde`。这两个键已移除，普通军事舰队不使用其旧建造/科研操作。
修正后需完全重新启动加载；修正本身仍需要再次检查引擎日志与实际动作。
同时启用的补员倒计时试验有独立的事件选项解析错误，不能据此判断本工具的窗口行为。

## 0.1.2：移动候选与稳定翻页

玩家反馈：日常停止所有舰队后扫描似乎能够合并，移动舰队不参与、部分翻页体验异常；
尚未测试极端情况。日志记录了合并请求，但同时仍有动作解析错误，因此不能用请求日志
独立确认实际合并成功。

- 放开普通移动、环绕、跟随、返回和通道使用。确认后只清除来源小队的旧命令，
  接收队继续原移动；预览仍不改变命令。
- 保护名单进入时生成一次固定编号；切换保护状态保留当前页。支持上一页、下一页、
  显式刷新，边界处隐藏不可用翻页按钮。新建/销毁舰队后可显式刷新名单。
- 预览时给每个设计分配固定组号，分组详情按组号分页，返回预览再进入仍保留当前页。
  排除组后重新规划会重建组号并回到第一页。
- 日志中裸合并动作即使使用`root.event_target:`仍被解析器拒绝。现改用
  `find_closest_fleet → found_fleet → merge_fleet` 的完整动作结构，并指定唯一目标与
  `allow_ftl=yes`。[合并脚本作者演示（2021）](https://www.youtube.com/watch?v=2fTmZsPovBY)
  提供此结构的旧版用例，当前4.5.2仍需要再次实机核验，不能把旧版用例当作验收通过。
- 接收目标使用固定的命名来源解析，减少动态`@this`在切换作用域时的歧义。

十项离线回归已通过，新增覆盖普通移动候选、保留维修等任务、九支舰队跨三页切换保护、
九个设计前后翻页与返回后页码保持。离线模型不验证原版动作解析、实际在途改令和寻路。
加载0.1.2需完全重新启动游戏，无需添加新的插件或重新注册播放集。
